# GPT 경유점을 이용한 후속 탐색 알고리즘 실험

기존 GPT-4o mini 재현 v2의 저장된 경유점과 동일한 100개 지도·1,000개
출발·도착 쌍을 사용했다. 프롬프트와 API 응답을 바꾸지 않았다. 이미 전체
GPT 결과를 살펴본 뒤 시작한 **추가 탐색 실험**이므로 독립적인 새 검증으로
표현하지 않는다. 각 결과는 같은 컴퓨터의 Python 3.12 재실행끼리
비교했고, 원본 재현의 실패 사례는 계속 실패로 둔다.

## 실험 1: 경유점 전환 시점

원본 구현은 다음 경유점을 이웃 칸으로 발견하기만 해도 탐색 목표를
바꾼다. 장애물 너머의 칸이거나 실제로 방문하지 않은 칸일 수 있으므로,
그 경유점을 heap에서 꺼내 실제로 탐색했을 때만 목표를 바꾸는 규칙을
시험했다. 기존의 이웃 발견 규칙을 대조군으로 유지했다.

Few-Shot 유효 사례 878건에서 원본 휴리스틱과 이 규칙을 조합하면
원본보다 탐색 횟수가 **1.290배**, 저장 항목 수가 **1.151배**가 됐다.
`goal=2, waypoint=0.5`와 조합해도 이웃 발견 규칙보다 탐색 횟수가
**1.040배**, 저장 항목 수가 **1.016배**였다. 경로 길이는 0.997배로
조금 짧아졌다. 탐색량 증가가 크므로 이 규칙은 채택하지 않았다.
재실행 파일: `scripts/evaluate_gpt_switch_rule.py`,
`experiments/gpt_switch_standard_summary.json`.

## 실험 2: 출발점에서 보이는 경유점 사용

이전의 엄격한 선택 규칙은 출발점→경유점과 경유점→도착점의 두 직선이
모두 장애물과 교차하지 않아야 경유점을 썼다. 이는 출발점에서 안전하게
도달 가능한 경유점도, 이후 직선 구간에 장애물이 있다는 이유로 버릴 수
있다. 새 규칙은 **출발점→경유점의 직선만 안전**하면 사용한다. 단,
출발점→도착점의 직선이 막혀 있어야 하고, 경유점을 통한 직선 거리 합은
직접 거리의 1.25배 이하여야 한다. 후보가 여러 개면 거리 비율이 가장
작은 점 하나를 쓴다. 경유점 사용 시 `f=g+2d(goal)+0.5d(waypoint)`,
그 외에는 `f=g+2d(goal)`로 탐색한다.

| GPT 프롬프트 | 유효 사례 | 선택 작동 | 새 규칙 / static weighted A*: 탐색 횟수 | 저장 항목 | 경로 길이 |
|---|---:|---:|---:|---:|---:|
| Few-Shot | 878 | 621 | 0.951 [0.938, 0.965] | 0.978 [0.971, 0.984] | 1.005 [1.003, 1.007] |
| CoT | 971 | 565 | 0.966 [0.953, 0.979] | 0.984 [0.978, 0.990] | 1.002 [1.001, 1.004] |
| RePE | 944 | 506 | 0.968 [0.956, 0.981] | 0.986 [0.980, 0.991] | 1.003 [1.002, 1.005] |

비율은 유효한 짝 사례별 후보/대조군의 기하평균, 구간은 지도 단위
5,000회 bootstrap의 95% 구간이다. 모든 유효 사례에서 경로 유효성
검사를 통과했다. 탐색 횟수와 저장 항목 수는 3개 프롬프트 모두에서
static weighted A*보다 줄었지만, 경로 길이는 **0.2~0.5% 늘었다**.
원본 LLM-A* 대비 탐색 횟수 비율은 Few-Shot 0.669, CoT 0.698,
RePE 0.648이고 경로 길이는 각각 0.998, 0.997, 0.998이다.
원본 대비 경로 길이의 작은 차이는 프롬프트에 따라 신뢰구간이 1을
포함하므로 확실한 단축으로 해석하지 않는다.

새 규칙은 `baseline/run_query.py --method start_visible_waypoint`에서
단일 지도/API 입력에도 적용할 수 있다. 저장된 응답을 흉내 낸 검사에서
오프라인 재실행과 탐색 횟수, 저장 항목, 경로가 일치했다. 실제 API 호출을
포함한 통합 실행은 아직 하지 않았다. 재실행 파일은
`scripts/evaluate_relaxed_gate.py`와 `experiments/gpt_relaxed_*`이다.

## 논문 대조군과 구분

우리의 static weighted A*는 `f=g+2d(goal)`로 가중치가 고정된다.
[원 논문의 Table 1](https://arxiv.org/pdf/2407.02511)은 초기 가중치
2에 0.99 감쇠를 쓰는 **Dynamic WA***를 싣는다. 따라서 우리 static
대조군 숫자와 논문의 Dynamic WA* 숫자를 같은 알고리즘 결과로
비교하지 않는다. 모델도 논문은 GPT-3.5/Llama3, 이번 실험은 GPT-4o
mini다.

## 보고서에서의 위치

첫 번째 후속 시도는 실패 사례로, 두 번째는 탐색량 개선과 경로 길이의
교환을 보여주는 추가 후보로 적을 수 있다. 저장된 GPT 전체 결과를 본
뒤 규칙을 수정했으므로 두 번째 결과는 **탐색적 결과**라고 명시한다.
미지의 지도나 새 API 응답에서도 같은 이득이 난다는 검증은 아니다.

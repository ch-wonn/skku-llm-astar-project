# GPT-4o mini 재현 결과를 이용한 개선 실험

## 실험 출처와 질문

재현 담당자의 `baseline/jooha-reproduction-v2` 커밋
`1aba737500008778868dde1896ea3c8514c84ff5`가 공개 100개 지도 ×
지도별 10개 출발·도착 쌍에 대해 저장한 응답을 사용했다. 모델은 GPT-4o mini,
프롬프트는 standard(Few-Shot), CoT, RePE이며 각 조건에서 1,000번 요청했다.
초기의 `gpt4omini_standard` 결과는 모든 응답에서 경유점 파싱에 실패했으므로
이 분석에 넣지 않았다.

질문은 **같은 LLM 경유점을 유지한 채 탐색 우선순위만 바꾸면 원본
LLM-A*의 탐색량과 경로 길이를 개선할 수 있는가**이다. Gemini 파일럿에서
정한 후보를 GPT 기록에 적용했으며 GPT 결과를 보고 매개변수를 조정하지
않았다. API 재호출은 없었다.

## 비교 방법

- 원본: `f = g + d(goal) + d(current waypoint)`.
- 목적지 비중 2: `f = g + 2d(goal) + d(current waypoint)`.
- 목적지 비중 2, 경유점 비중 0.5: `f = g + 2d(goal) + 0.5d(current waypoint)`.
- LLM 없는 대조군: `f = g + 2d(goal)`인 가중 A*.
- 선택적 경유점: 출발점과 목표점의 직선이 장애물과 교차하고, LLM 경유점
  하나를 통한 두 직선은 모두 교차하지 않으며 우회율이 1.25 이하일 때만
  그 경유점을 사용한다. 이때 목적지 비중 2, 경유점 비중 0.5를 쓰고,
  그 외에는 LLM 없는 가중 A*와 같은 탐색 우선순위를 쓴다.

각 조건에서 재현 결과가 유효한 사례만 같은 지도와 같은 LLM 응답으로
짝지어 비교했다. 따라서 유효 사례 수는 standard 878, CoT 971, RePE
944이며 실패 사례를 성공으로 바꾸지 않았다. 비율은 사례별 후보/대조군
비율의 기하평균이다. 신뢰구간은 지도 100개를 단위로 복원추출한 5,000회
bootstrap의 95% 구간이다. `operation`은 원본 구현의 heap pop 횟수,
`storage`는 `g` 딕셔너리 항목 수다. 실행 시간이나 실제 RAM 사용량이 아니다.

## 결과

| 프롬프트 | 유효 사례 | 목적지 2·경유점 0.5 / 원본: operation | storage | length |
|---|---:|---:|---:|---:|
| standard | 878 | 0.727 [0.697, 0.759] | 0.844 [0.826, 0.863] | 0.995 [0.992, 0.998] |
| CoT | 971 | 0.739 [0.709, 0.768] | 0.854 [0.837, 0.872] | 0.997 [0.995, 0.999] |
| RePE | 944 | 0.689 [0.656, 0.721] | 0.821 [0.802, 0.840] | 0.997 [0.995, 0.999] |

원본보다 탐색 횟수는 약 26~31%, 저장 항목 수는 약 15~18% 줄었다.
경로 길이는 평균 비율이 1보다 조금 작다. 그러나 이 후보의 탐색 횟수는
LLM 없는 가중 A*보다 standard 3.3%, CoT 2.2%, RePE 2.9% 많았다.
이 대조군을 빠뜨리면 경유점이 성능 향상에 필수적인 것처럼 보일 수 있다.

| 프롬프트 | 선택적 경유점 사용 | 선택적 경유점 / 가중 A*: operation | storage | length |
|---|---:|---:|---:|---:|
| standard | 165/878 | 0.984 [0.976, 0.991] | 0.993 [0.989, 0.996] | 1.000 [0.999, 1.000] |
| CoT | 178/971 | 0.984 [0.976, 0.991] | 0.993 [0.989, 0.997] | 0.999 [0.998, 1.000] |
| RePE | 160/944 | 0.987 [0.978, 0.994] | 0.995 [0.992, 0.998] | 1.000 [0.999, 1.000] |

선택적 경유점 방법은 가중 A*보다 탐색 횟수가 약 1.3~1.6% 적었고
경로 길이 차이는 작았다. 경유점 사용 사례에서 탐색 횟수 개선/동률/악화는
standard 61/89/15, CoT 66/94/18, RePE 59/83/18건이다. 즉 선택
조건이 악화 사례를 전부 제거하지는 못한다. 별도의 LLM 호출은 없지만
경유점 검사와 기존 LLM 호출 자체의 비용은 이 탐색량 비율에 포함되지 않는다.

## 검증과 해석 한계

모든 유효 사례에서 다섯 후보와 원본 및 A*의 경로가 유효했다. 저장된
재현 수치와 Windows/Python 3.12 재실행 수치가 정확히 일치하는 사례는
원본 LLM-A* 기준 standard 858/878, CoT 948/971, RePE 922/944였다.
경로까지 일치하는 사례는 각각 874, 966, 938건이다. 두 불일치 사례를
실제 재현 코드를 Windows에서 실행해보니 재실행 코드와 동일한 탐색 횟수가
나왔다. 원래 저장 결과는 Linux/Python 3.11에서 생성됐으므로 실행 환경에
따른 부동소수점 동점 순서 차이와 부합하지만, 모든 차이의 원인을 증명한
것은 아니다. 따라서 후보와 대조군은 **같은 Windows/Python 3.12
재실행**으로 비교했다. 공식 재현 수치 자체를 수정하지 않았다.

세 프롬프트는 같은 100개 지도에 대한 서로 다른 응답이므로 독립된
3개 데이터셋이 아니다. 신뢰구간은 지도 간 변동만 보여주며 API 응답을
다시 받을 때의 변동은 추정하지 않는다. 파싱/API 실패 사례에서는 어떤
개선 후보도 실행하지 않았으므로 성공률은 재현 결과와 같다.

재실행: `python scripts/evaluate_gpt_v2.py --results-root
baseline/experiment_results/reproduction_v2 --prompt standard --output
experiments/gpt_v2_standard.jsonl --summary-output
experiments/gpt_v2_standard_summary.json` (`cot`, `repe`도 같은 방식).
이 명령은 재현 v2 결과가 현재 checkout에 있을 때 작동한다.

## 현재 판단

목적지 2·경유점 0.5는 원본 LLM-A*보다 뚜렷하게 개선되지만 LLM 없는
가중 A*에 근소하게 못 미친다. 선택적 경유점 방법은 LLM 없는 대조군을
근소하게 앞섰으나 이득이 작고 LLM 호출 비용을 정당화하지는 않는다.
보고서의 주요 개선 결과는 목적지 2·경유점 0.5로 두고 LLM 없는 대조군과의
비교를 함께 제시한다. 선택적 경유점 방법은 추가 실험으로 분리한다.
두 방법 모두 `baseline/run_query.py`에서 단일 지도 입력을 받을 수 있고,
저장된 GPT 응답을 흉내 낸 검사는 오프라인 재실행과 일치했다. 실제 GPT
API를 통한 통합 호출과 Ubuntu 22.04/Python 3.11 빈 환경 검사는 남아 있다.
